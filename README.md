### 🔴 核验中发现并修复的真 Bug

农历转换原有一处**周期归属判据错误**：农历十一月起于冬至前的朔日，
而原代码用「日期 < 冬至」判断归属，导致每年 12 月有数天被错划，产生 `lDay = 385` 这类荒谬值。

- 影响范围：1717 天样本中 **39 天错误**（1998 错 3 天 / 2020 错 6 天 / 2023 错 9 天 / 2024 错 20 天 / 2025 错 1 天）
- **原先自选的 10 个锚点全部避开了这个窗口，所以曾 100% 通过**——这正是自测的盲区
- 已修复，并将静默失败改为抛错，防止错误数据污染下游排盘
- 修复后 5535 天全对

## 📚 知识库（RAG）——AI 的回答依据

AI 不是凭空发挥，每次回答前系统会从**《紫微斗數全書》原文**中检索相关条目，塞进 prompt 让模型依据原文作答。

### 语料来源

| 项 | 说明 |
|---|---|
| 典籍 | 《紫微斗數全書》全三卷（明·万历本系统，题陈希夷撰、罗洪先编） |
| 获取 | 中文维基文库 <https://zh.wikisource.org/wiki/紫微斗數全書> |
| 版权 | 公有领域（作者逝世逾百年） |
| 体量 | 原始 wikitext 约 211 KB（卷一 67.7KB / 卷二 106.7KB / 卷三 36.7KB） |
| 结构化后 | **460 条**，存于 `knowledge_base.js`（283 KB） |

条目分类：

| 类型 | 条数 | 内容 |
|---|---|---|
| `palace_star` | 388 | 卷二「某星在某宫」断语，如「破军在夫妻宫」 |
| `star_general` | 26 | 卷一〈諸星問答論〉各星总论 |
| `treatise` | 20 | 论命体例、格局篇章 |
| `classic_verse` | 14 | 骨髓赋、太微赋等歌诀 |
| `palace_all` | 12 | 十二宫各宫总纲 |

### 检索机制：命盘驱动的精确召回（不是向量检索）

这是有意的架构选择，不是技术妥协。

命理检索的 key 是**完全确定**的——排盘算完后，系统已经知道「夫妻宫坐破军、庙、对宫廉贞天相、生年化禄在贪狼」。这种情况下精确查表比 embedding 相似度更准，而且纯前端零依赖就能跑，不需要向量数据库、不需要 embedding API。

召回优先级：

1. 夫妻宫主星的宫位断语 + 该星总论
2. 宫内无主星 → 借对宫主星（符合传统借星安宫法）
3. 命宫主星
4. 夫妻宫的吉星煞星
5. 生年四化所涉星曜
6. **按问题主题定位宫位**：事业→官禄宫、催婚/父母→父母宫、钱/买房/彩礼→田宅宫、朋友/第三者→交友宫、孩子→子女宫、焦虑/内耗→福德宫、异地→迁移宫、身体→疾厄宫

预算控制：最多 14 条 / 单条截断 420 字 / 总量 3200 字符。实测平均每次注入约 2100 字符典籍原文，召回 10–12 条。

### 🔴 重要：语料有转录讹误，因此严格分层

比对时发现维基文库的文本存在转录错误，例如：

- 「壬癸**免**蛇藏」——「兔」误录为「免」
- 「丙丁猪**狗**位」——按天钺安星规则应为「猪**鸡**位」（亥酉，非亥戌）

这意味着**古籍文本不能直接拿来当算法依据**。本项目因此做了硬性分层：

| 层 | 来源 | 用途 | 可信度 |
|---|---|---|---|
| **A 算法层** | 本项目代码（VSOP87 + Meeus + 安星诀） | 排盘计算 | ✅ 已用香港天文台官方数据 + iztro 交叉验证 |
| **B 知识层** | 《紫微斗數全書》原文（RAG） | 文字解读 | 🟡 真古籍，但存在转录讹误 |
| **C 创作层** | 项目手写文案 | 无 key 时的内置引擎兜底 | ❌ 现代创作，无法考据 |

**B 层绝不参与 A 层计算。** 这条原则已写进 `kb/build_kb.py` 和 `knowledge_base.js` 的文件头注释，请勿推翻。

### 古籍语言的现代化转译

原文用词极为严苛（克、刑、孤、淫、破败、夭折）。system prompt 中有强制约束：

- 必须优先依据检索到的原文作答，并**显示出处**（如「卷二·三妻妾」）
- **必须**把严苛字眼转译为现代视角（「克」→ 关系中的消耗与磨合模式），**严禁**把原文恐吓字眼直接丢给用户
- 检索结果与问题无关则忽略，**绝不可编造原文或杜撰出处**

### 八字知识库

紫微之外，八字解读也接了独立的 RAG。

| 典籍 | 体量 | 用途 |
|---|---|---|
| 《窮通寶鑑》（栏江网） | 100 KB | **调候**，按「日干＋月令」组织，本库主干 |
| 《淵海子平》明·杨淙 | 173 KB | 十神论、六亲论、性情、疾病、女命 |
| 《滴天髓》题刘基 | 37 KB | 义理通论 |

#### 为什么走「调候」这条路

八字 RAG 有个绕不开的难题：传统解读要先判**旺衰**、取**用神**，而这恰恰是八字流派分歧最大的环节，不同门派结论不同，无法外部验证。**一旦判错，整条检索链全错。**

《窮通寶鑑》的组织方式解决了这个问题——它按 **日干 + 月令** 编排：

```
=== 三春甲木 ===
  正月甲木，初春尚有余寒，得丙癸逢，富贵双全…
  二月甲木，庚金得所，名阳刃驾杀，可云小贵…
```

而「日干」和「月支」是排盘直接确定的硬事实，不需要任何主观判断。

> [!IMPORTANT]
> 本项目**刻意不以「身强身弱／用神」作为检索 key**。
> 这不是能力不足，是有意规避——用无法验证的判断做检索入口，等于把不确定性放大到整条链路。

#### 调候覆盖矩阵（10 干 × 12 月）

```
        正 二 三 四 五 六 七 八 九 十 十一 十二
  甲木  ●  ●  ●  ●  ●  ●  ●  ●  ●  ●  ●   ●
  乙木  ●  ●  ●  ●  ●  ●  ●  ●  ●  ●  ●   ×
  丙火  ●  ●  ●  ●  ●  ●  ●  ●  ●  ●  ●   ●
  丁火  ●  ●  ●  ●  ●  ●  ●  ●  ●  ○  ●   ○
  戊土  ○  ○  ○  ●  ●  ●  ○  ●  ●  ●  ●   ●
  己土  ●  ●  ●  ○  ○  ○  ○  ○  ○  ○  ○   ○
  庚金  ●  ●  ●  ●  ●  ●  ●  ●  ●  ●  ●   ●

  壬水  ●  ●  ●  ●  ●  ●  ●  ●  ●  ●  ●   ●

  ● 有本月专条 104 格    ○ 原书该季不分月，以季节总论代 15 格    × 原书缺 1 格
```

`○` 与 `×` 不是程序的遗漏，而是《窮通寶鑑》本版原文如此——例如「三春戊土」通篇不分月，「三冬乙木」只写到十一月。检索器遇到这两种情况会在 prompt 顶部加 `※` 提示，并**要求 AI 如实告知用户「此处依据颗粒度较粗」**，不允许假装有精确依据。

#### 分析层：只算硬事实

`bazi_analyze.js` 把四柱展开成确定性检索 key：

- 地支藏干（人元司事通行本）
- 四柱十神 + 藏干十神
- 五行分布（天干 1 分，藏干本气 1／中气 0.5／余气 0.3）
- 月令、季节、调候坐标
- 配偶星（男看财、女看官杀）是否透出

验证：38 项断言全通过，含 12 个月令映射全覆盖、1998-08-18 与 2000-01-01 两张全盘手推核对。

#### 构建过程中修掉的 3 个真 Bug

| # | 问题 | 症状 | 修复 |
|---|---|---|---|
| 1 | 章节正则越界 | `=== 三冬丁火 ===` 会吞掉后面 `== 论土 ==` 整节，造成「戊土二月有专条」的假阳性 | 前瞻改为 `(?=^==)`，同时拦住二级与三级标题 |
| 2 | 月份连写误读 | `十一二月` 被解析成「11 月和 **2** 月」，实为「11 月和 12 月」 | 前一个值 ≥10 时，后续个位数按 10+d 读 |
| 3 | 段落边界串段 | 原文 `…方妙。\n\n或'''八月'''一派辛金`，句首的「或」被切给了七月 | 段尾连接词移交给下一段，并补回月份标签 |

Bug 1 的性质值得一提：它制造的是**假阳性**——修复后覆盖率从「看起来更高」变成「如实反映原文」。

#### 双体系如何共存

紫微和八字是两个坐标系，硬凑一致是造假。prompt 里明确规定：

- 紫微回答「**在哪个场域、什么时候**」——十二宫定领域，四化大限流年定时机
- 八字回答「**这个人的底色与节奏**」——日主五行与调候定气质，十神定关系模式
- 两边不一致时，**如实说明分歧**并给出综合判断的理由，**严禁为显得权威而捏造一致性**

#### 额外的语料防护

八字典籍比紫微更需要转译，prompt 中另加了两条硬约束：

- 这批书写于科举时代，满纸「科甲」「显宦」「命妇」「常人」。**严禁照搬阶层判词**，须转译为发展节奏与资源条件。
- 《淵海子平》以男性为默认视角（「正财为妻」「论妻妾」）。对女性用户须按关系换算（女命以官杀为配偶星），不得直接套用原文性别预设。
